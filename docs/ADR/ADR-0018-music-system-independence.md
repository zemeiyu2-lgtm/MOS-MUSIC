# ADR-0018｜MOS Music 独立定位冻结（音乐系统 ⟂ 门训系统）

- 状态：**Frozen（产品方向冻结）**
- 日期：2026-09-23
- 关联：ADR-0002（双流程边界）、ADR-0003（map 不是第三套体系）、ADR-0017（单曲完整单元标准层）

## 背景

MOS Music 在 V3.0 已完成单曲 18 段结构、L1–L4 派生、十步教学法、学唱 / 视唱 / 教唱、简谱核心、
男女示唱与钢琴资源模型、时间轴与光标，并已让前台与 52 周课程解耦。

但「解耦」还只是一个工程事实，没有被写成产品定位。若不冻结定位，后续 100 首歌曲生产会被三股力量拉回去：
① 以周次 / 课程 / 讲章为组织中心；② 把音乐做成门训课程的附件；③ 让歌曲只能通过「某一周」被看见。

## 决策

> **MOS Music 是独立的音乐学习、歌唱训练、教唱与生命形成系统。**

明确四条：

1. **不以 52 周经文为组织中心。**
2. **不以门训课程为组织中心。**
3. **不以讲章为组织中心。**
4. **歌曲自身可以独立成立。**

关系（不是从属，而是相连）：

- 课程可以引用音乐；
- 音乐也可以被课程引用；
- 两者相连，但**互不从属**。

## 落地约束（可执行）

| 面 | 约束 | 执行方式 |
|---|---|---|
| 前台 | **不突出 W01 / W02 / W03……** | `tools/guard.js` 检查 `app/front/**` 不得出现 `W\d{2}` 与课程 / 年度单元 ID |
| 后台 | **保留历史引用关系** | 年度周记录、单元记录、周音乐模块全部保留；`guard` 检查年度索引非空，**不得删除已有后台 Week Music 数据** |
| 内容 | 歌曲内容属于歌曲本身 | `content/song-content/**` 六项字段，校验器禁止出现周次 / 课程码 |
| 生产 | 单曲单元是独立层 | 单元不引用周次（ADR-0017 继续有效） |

## 后果

- 一首歌可以被「没有课程的人」完整使用（看谱 → 钢琴陪唱 → 跟唱 → 教学），这是本决策的直接目的。
- 门训系统仍然可以用音乐，但方式变成「引用」，而不是「拥有」。
- 100 首歌曲的生产不再以「有没有对应的周」为前提。

## 不做什么

- 不删除、不改写任何后台历史引用关系；
- 不把音乐前台变成课程目录；
- 不因为本决策而修改任何既有研究裁决（辨识 / Tier / Review Status / 52W 经文中心）。
