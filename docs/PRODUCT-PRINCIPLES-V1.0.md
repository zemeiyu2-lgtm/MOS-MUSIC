# MOS-MUSIC 产品原则 V1.0

## 一、独立性

MOS-MUSIC 是独立产品。

它可以与 MOS 其他项目在技术或研究层面共享基础能力，但前台产品不与门训课程绑定。

禁止：
- 以 52 周课程作为歌曲主导航。
- 在歌曲页面显示课程依赖。
- 以课程完成推动音乐学习。
- 把歌曲解释成某一门训课程的附属材料。

歌曲本身就是完整的音乐学习单元。

## 二、用户核心路径

### 普通用户

诗歌本 → 找到歌曲 → 听 → 学 → 唱

### 进阶用户

歌曲 → 简谱 → 视唱 → 独立唱

### 教师

歌曲 → 乐句 → 示范 → 教唱提示 → 带人唱

## 三、界面原则

一级导航应尽量少。

优先保留：
- 诗歌本
- 学习
- 我的歌

歌曲内部：
- 听
- 学
- 唱

专业功能通过歌曲内部状态进入，不抢占首页。

## 四、视觉方向

关键词：

现代 / 简洁 / 音乐化 / 年轻 / 流动 / 有呼吸感 / 流行音乐产品感

避免：

厚重课程后台感 / 表格感 / 管理系统感 / 神学院门户感 / 复杂仪表盘感。

## 五、内容完整性

完整歌曲单元至少应逐步具备：

1. 简体中文歌词
2. 正式简谱
3. 可播放声音
4. 钢琴练习
5. 示唱
6. 乐句结构
7. 学唱
8. 视唱
9. 教唱

只有资源真正存在并通过验证，才显示“可用”。

## 六、内容原则

英文标题可以作为内部来源检索字段，但前台歌曲内容以简体中文为准。

缺少的内容：
- 不虚构
- 不伪造
- 不用“资源存在”代替“用户可以使用”

## 七、AI 边界

Singing Coach 可以辅助：
- 音准
- 节奏
- 延音
- 咬字
- 强弱
- 表达

不得评分：
- 属灵程度
- 敬拜真诚度
- 灵命状态
- “更属灵”的程度

## 八、工程原则

- 优先复用已有 Player。
- 优先复用已有 Learn / Sight / Teach。
- 优先复用现有 teaching 数据层。
- 不建立重复数据层。
- 真实媒体必须经过浏览器实际播放/渲染验收。
