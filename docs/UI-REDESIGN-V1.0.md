# MOS-MUSIC 前台界面重整基线 V1.0

日期：2026-09-25
状态：UI implementation baseline

## 目标

本轮不是增加功能，而是减法、收口、重排、隐藏复杂度，把现有音乐能力重新组织成现代音乐产品。

核心原则：现代的是产品体验，不是把经典歌曲改造成流行歌。经典圣诗、传统中文诗歌、当代诗歌可以共存。

## 一、产品一句话

让经典今天继续被听见、学会、唱起来。

## 二、一级信息架构

桌面端采用：左侧栏 + 主内容区。

左侧栏只放三个一级入口：
1. 诗歌本
2. 学习
3. 我的歌

搜索、设置可以放在侧栏底部或顶部辅助区域。

移动端折叠为简洁导航，保持同一套信息架构。

不把 Singing Coach 放入一级导航。

## 三、首页重新定义

现有首页的信息块过多。首页只解决三件事：

- 找到歌
- 现在唱
- 继续学

首页不做仪表盘，不显示课程数量、周次、门训进度、内容治理、资源状态、生产状态等信息。

## 四、诗歌本

诗歌本是核心页面。

顶部：搜索歌曲。

其次保留少量个人过滤：全部、收藏、正在学、最近唱过。

发现分类保留四个维度：主题、处境、场景、音乐，但默认收起，不让筛选器占据页面。

歌曲卡只显示：封面、简体中文歌名、简短说明、播放、收藏。

Song ID、Tier、Review Status、资源状态、工程字段不得在普通歌曲卡上出现。

## 五、歌曲页

歌曲页从资料展示页改成播放器 + 歌曲学习空间。

第一屏回答三个问题：这是什么歌？现在能不能听？我要怎么开始？

第一屏优先显示：封面、歌名、播放、男声示唱、女声示唱、钢琴、速度、收藏、极短简介。

主体顺序：听 → 看 → 学 → 唱。

### 听

播放器是主角。只保留播放/暂停、进度、速度、音轨、循环。

### 看

直接显示完整简谱；歌词自然靠近简谱。

不要再使用大量后台式编号区块。

### 学

点击开始学，进入现有 Learn 引擎。乐句卡属于学习内部结构，不在歌曲主页堆成数据库列表。

### 唱

提供自己唱、变速、单句练习、视唱。

Teach 属于专业入口，不与其他模式同时占据大量首页空间。

## 六、专业能力的位置

Learn / Sight / Teach / Singing Coach 全部保留，但降级为歌曲内部能力。

前台语言优先使用：
- 学唱
- 看谱唱
- 教别人
- 唱得更准

Singing Coach 的自然入口是：歌曲 → 唱 → 唱得更准。

## 七、懂·活内容

保留歌曲自身的内容理解、圣经根基、背景、反思、实践、祷告。

但它们放在歌曲页较下方或折叠区域，不压住播放器、歌词和简谱。

## 八、经典与现代

现代体现在导航、排版、播放器、搜索、动效和交互。

经典圣诗、传统旋律、经典简谱不需要被强行流行化。

核心定位：经典不过时，现代仍需要经典；经典可以自然进入现代人的生活。

经典歌曲可以保留纸张感、乐谱感、留白和温暖感；当代歌曲可以使用更大胆的视觉语言，但整个产品仍属于同一品牌。

## 九、视觉

现有深绿 / 暖白 / 暖金方向可以保留，但减少课程后台感。

建议关键词：现代、简洁、音乐化、流动、有呼吸感、温暖、克制、流行音乐产品感。

减少边框、状态 chip 和技术性小字，让歌曲封面、歌词和简谱成为视觉主角。

## 十、后台与前台边界

以下内容继续保留在后台，不删除工程能力：
- W01 / W02 / W03
- 24 课
- 七步音乐门训
- Course ID
- production console
- calibration
- resource discovery
- governance
- tier
- review_status
- source_required
- CI 编号
- 内容生产状态

原则：后台可以复杂，前台必须简单。

## 十一、歌曲完整性

完整歌曲标准：
1. 简体中文歌词
2. 正式简谱
3. 可播放声音
4. 钢琴
5. 示唱
6. 乐句
7. 学唱
8. 视唱
9. 教唱

缺失时如实显示“待提供”，不得用假按钮、占位谱或假音频冒充完整。

## 十二、首批 UI 样板

优先使用：
- S-0001《奇异恩典》
- S-0002《我灵镇静歌》
- S-0004《普世欢腾歌》

S-0003 / S-0005 的缺谱或缺琴继续走内容生产，不用 UI 假装完整。

## 十三、实施原则

1. 不重写 Player。
2. 不重写 Learn。
3. 不重写 Sight。
4. 不重写 Teach。
5. 不删除内容层。
6. 不删除后台研究数据。
7. 不删除现有测试。
8. 优先通过 shell、CSS、front views 做信息层级重排。
9. 真正涉及数据结构时单独评估。
10. 改完必须进行真实用户路径测试。

## 十四、最终体验

不要让用户觉得“这里功能很多”。

希望用户感觉：

这里有很多值得唱的歌，我知道下一步做什么。

核心路径：找到一首歌 → 听 → 看谱 → 学一句 → 唱一句 → 再唱 → 整首唱起来。
